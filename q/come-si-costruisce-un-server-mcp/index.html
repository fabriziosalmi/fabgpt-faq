Come si costruisce un server MCP?

Un server MCP è più semplice di quanto suoni: un processo che espone tool tipizzati (nome, schema dei parametri, descrizione) su stdio o HTTP, e risponde alle chiamate. Con gli SDK ufficiali (Python/TypeScript – FastMCP rende il Python quasi dichiarativo), un tool è una funzione decorata: nome, docstring, tipi – lo schema si genera da solo.

Le scelte che separano un giocattolo da un server serio:

  • descrizioni scritte per il modello: il tool viene scelto in base a nome e descrizione – ambigue = tool ignorato o abusato
  • tool stretti: dieci strumenti specifici e tipizzati battono un run_command generico – è il principio dei permessi applicato al design
  • output parchi: il risultato finisce nel contesto – pagina, filtra, riassumi
  • registro fisso e auditabile per i contesti seri: proxxx blocca i suoi 25 tool a compile-time, per la supply chain

Esempi nel portfolio da cui copiare: l0-memory (Go, stdio+CLI), agssh (scansioni da agente).
