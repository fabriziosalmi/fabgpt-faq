Come si dimensiona un nodo Proxmox (CPU, RAM, dischi)?

L'ordine dei colli di bottiglia, imparato da tutti nello stesso modo:

  • la RAM finisce per prima: le VM la prenotano, ZFS vuole il suo ARC (regola: limitalo, o si prende metà macchina), e l'overcommit di memoria è molto meno indulgente di quello CPU. Somma le VM previste, aggiungi 4-8 GB per host e ARC, arrotonda in su
  • CPU: si overcommitta serenamente 3-4:1 sui core per carichi misti – i container quasi non contano, le VM da lavoro contano parecchio. Più core medi battono pochi core veloci, salvo licenze per-core
  • dischi: un mirror NVMe per sistema e VM è il singolo upgrade che cambia la vita (niente RAID hardware sotto ZFS); i dischi grossi e lenti per backup e media, mai sullo stesso pool delle VM
  • rete: 2.5G ormai regalato, 10G se c'è storage di rete di mezzo; una NIC in più per corosync nei cluster

E quando il carico cambia nel tempo, l'autoscaling tiene le risorse allineate al posto tuo.
