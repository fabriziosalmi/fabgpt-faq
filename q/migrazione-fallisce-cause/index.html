Proxmox e self-hosting

La migrazione fallisce: cause tipiche

L'errore della migrazione dice quasi sempre la causa – va solo letto. Le solite cinque:

  • risorse locali agganciate: una ISO montata da storage locale, un dispositivo USB o una GPU passata – la VM è inchiodata al ferro finché non li stacchi (Hardware → rimuovi/ejetta, poi riprova)
  • storage assente sul nodo di destinazione: il disco vive su uno storage che l'altro nodo non vede → storage condiviso, oppure --with-local-disks per la copia a caldo
  • CPU type incompatibile: VM con CPU host verso un processore diverso → tipo comune (x86-64-v2/v3) e un riavvio pianificato per applicarlo
  • RAM insufficiente di là: il nodo di destinazione deve contenere la VM – libera o scegli un altro nodo
  • rete/quorum ballerini: migrazioni che si interrompono a metà con cluster instabile → prima si guarisce il quorum, poi si migra; e un lock residuo dopo il fallimento si toglie con qm unlock

Per i container: la migrazione è a freddo (restart) – se "fallisce" perché la vuoi live, non è un bug, è il design.
