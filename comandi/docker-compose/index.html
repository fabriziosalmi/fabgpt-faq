# Come tiro su e giù uno stack Compose?

docker compose up -d
docker compose down

down NON tocca i volumi; down -v li cancella – differenza da sapere a memoria.

# Come forzo la ricreazione (e la rebuild) dei servizi?

docker compose up -d --force-recreate --build

--build ricompila le immagini locali; --force-recreate ricrea anche senza modifiche.

# Come riavvio un solo servizio dello stack?

docker compose restart <servizio>
# con nuova immagine o config: docker compose up -d <servizio>

restart non ricarica immagini né variabili: per quelle serve up -d sul servizio.

Approfondisci: Cos'è Docker Compose?

# Come aggiorno le immagini di uno stack Compose?

docker compose pull && docker compose up -d

Ricrea solo i servizi con immagine nuova; per l'automatico c'è Watchtower – conoscendone i rischi.

# Come vedo i log di uno stack (o di un servizio)?

docker compose logs -f --tail 100 [servizio]

Senza nome del servizio aggrega tutto lo stack, con i prefissi colorati.

# Come vedo lo stato dei servizi dello stack?

docker compose ps

Mostra anche health e porte pubblicate: la fotografia dello stack in una riga per servizio.

# Come valido un compose file (ed env risolte)?

docker compose config

Stampa il file finale: variabili interpolate e override applicati – il debug di .env parte da qui.

# Come tengo modifiche locali senza toccare il compose principale?

# compose.override.yml viene fuso in automatico con compose.yml
docker compose config   # verifica il risultato della fusione

L'override è il posto per porte di debug e bind mount locali: il file principale resta pulito e committabile.

# ogni flag ha il suo campo YAML: -p->ports, -v->volumes, -e->environment, --restart->restart
